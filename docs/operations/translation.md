# 正体中文界面

本分支的桌面版与网页版界面显示正体中文。移动端、服务端错误信息与发给代理的提示词保持英文。

## 机制

- `apps/web/src/i18n.ts` 用 i18next 初始化语言，界面文字通过 `tr("英文原文", { 占位符 })` 取译文。
- 译文在 `apps/web/src/locales/zh-Hant.json`，键是英文原文，值是正体中文。值为空时界面回退到英文原文。
- 单元测试环境（`import.meta.env.MODE === "test"`）固定显示英文，测试断言沿用上游的英文文案。
- `scripts/i18n-wrap.ts` 扫描 `apps/web/src`，把界面文字改写成 `tr()` 调用，并按源码里实际用到的键重写语言包：新增的键留空，不再使用的键删除，已有译文保留。

## 合并上游后更新语言包

1. 合并上游并解决冲突。冲突发生在 `tr()` 调用处时，保留上游的新逻辑，文字部分交给下一步重新包装。
2. 运行包装脚本，它会输出改动的文件数与未翻译条目数：

   ```bash
   vp run i18n:wrap
   ```

3. 在 `zh-Hant.json` 中为值为空的键填写译文。占位符 `{{name}}` 保持原样；英文复数后缀占位符（如 `{{s}}`、`{{value}}` 取 `"s"`）在译文中省略。
4. 对改动范围做格式化、类型检查与网页单元测试：

   ```bash
   vp fmt apps/web/src scripts/i18n-wrap.ts
   ```

   ```bash
   vp run --filter @t3tools/web typecheck
   ```

   ```bash
   vp run --filter @t3tools/web test
   ```

## 包装规则的例外

脚本顶部的几张表决定哪些字面量不翻译，新增例外时改这里：

- `RENDER_KEYS`：逻辑里当作标识比较的状态文字，源码保留英文，在显示处用 `tr(status.label)` 翻译。
- `NOT_TEXT`：形似文字的代码字面量，例如占位命令、路径、发给代理的续接消息。
- `PROMPT_FILES`：拼装代理提示词的文件，只包装其中的属性与 JSX 文字。
- `UNWRAPPED_FILES`：整份不包装的文件，包括文字会写入用户设置或被逻辑比对的文件，以及在 i18n 初始化前运行的启动错误页。

包装后若出现英文字面量与 `tr()` 结果做比较的代码，比较会失效。这类位置改为比较 `tr()` 的结果，或把文字列入上面的例外。
